1. ⚙️ 后端性能与架构优化
数据预加载与内存缓存：

问题：当前每次调用 API 都通过 load_dataset() 重新读取磁盘上的 .parquet 或 .csv 文件，高并发或频繁翻页时开销极大。

建议：在 FastAPI 服务启动（lifespan 或启动事件）时，将 DataFrame 预加载到内存全局变量或使用 @functools.lru_cache 缓存数据，查询速度可提升几十倍。

硬编码 URL 优化（消除 localhost:8000）：

问题：后端直接返回 http://localhost:8000/maps/...，如果前端部署到手机测试、局域网或公网服务器，图片链接会直接失效。

建议：后端返回相对路径（如 /maps/xxx.gif），或通过环境变量配置 BASE_URL；前端拼接基准 API 域名。

静态资源 HTTP 缓存头：

挂载静态目录时，为地图图片设置长期缓存响应头（Cache-Control: max-age=86400），避免用户反复切换页面时重复下载相同的 GIF 图片。

2. 🎨 前端交互与 UX 体验提升
路线图交互体验（内置 Lightbox 放大预览）：
问题：详情页点击地图使用的是 window.open(map_url, '_blank') 另开新标签页，在移动端体验较差。

建议：引入简单的 Modal / Lightbox 放大组件，支持在当前页面直接全屏查看地图，并在移动端支持双指缩放（Pinch-to-zoom）与拖拽。

搜索框防抖（Debounce）与重置按钮：

在列表页搜索框增加 300ms 防抖处理，避免用户一边打字一边触发 API 请求。同时在筛选卡片右上角增加一个“一键重置所有筛选”按钮。

加载状态优化（骨架屏 Skeleton）：

用卡片骨架屏（Skeleton Screen）替代单纯的 Loading... 提示文本，能显著提升用户的“感知加载速度”。

响应式细节微调：

在移动端屏幕下，详情页顶部增加固定悬浮的“Back to Top”按钮或更明显的返回按钮，提升长页面滑动体验。
